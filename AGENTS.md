# Agent Guidelines for ampms-libs

This document provides essential information for AI coding agents working in this repository.

## Project Overview

**Type**: Monorepo (pnpm workspace) managed by Projen  
**Scope**: @ampms-libs  
**Tech Stack**: Effect, TypeScript, Vitest, pnpm  
**Architecture**: Effect-first functional programming with Schema-driven type safety

## Build, Test, and Lint Commands

### Root Level (run from project root)

```bash
pnpm build                # Build all packages
pnpm test                 # Run all tests
pnpm test:watch           # Run tests in watch mode
pnpm eslint               # Lint all packages
pnpm compile              # Compile TypeScript
pnpm watch                # Development watch mode
```

```bash
npm run build             # Build this package
npm run test              # Run tests for this package
npm run test:watch        # Watch mode for this package
npm run eslint            # Lint this package
npm run compile           # Compile TypeScript (CJS + ESM)
```

```bash
# From package directory
npm test -- service.test.ts

# Or with vitest directly
npx vitest run test/service.test.ts

# Watch mode for single test
npx vitest test/service.test.ts
```

## Code Style and Conventions

### Import Order (enforced by ESLint)

```typescript
// 1. Node built-ins first
import crypto from "node:crypto";

// 2. External libraries (alphabetically, case-insensitive)
import { HttpClient, HttpClientRequest } from "@effect/platform";
import { Effect, Layer, Schema } from "effect";

// 3. Local imports
import { makeHttpClient } from "./client";
import { CustomError } from "./errors";
```

### TypeScript Configuration

- **Strict mode**: All strict flags enabled
- **Target**: ES2020
- **Module**: Dual output (CommonJS in `lib/`, ESM in `lib/esm/`)
- **Always use explicit types** for function parameters and return values
- **Avoid `any`**: Use `unknown` and Schema validation instead

### Naming Conventions

- **Files**: lowercase-with-hyphens (e.g., `effect-yahoo-finance`)
- **Classes**: PascalCase (e.g., `YahooFinanceService`, `BadRequestError`)
- **Functions/Variables**: camelCase (e.g., `makeService`, `searchQuotes`)
- **Constants**: camelCase (e.g., `makeHttpClient`)
- **Effect Tags**: Full path format `"@ampms-libs/package-name/ServiceName"`
- **Error classes**: Use Error suffix (e.g., `NotFoundError`, `UnauthorizedError`)

## Effect Service Pattern (REQUIRED)

All services MUST follow this structure:

```typescript
const makeService = Effect.gen(function* () {
  const client = yield* makeHttpClient;

  const method1 = (options: Options) =>
    client.get("/path", { urlParams: options }).pipe(
      Effect.andThen(HttpClientResponse.schemaBodyJson(ResponseSchema)),
      Effect.catchTag("ResponseError", ({ response }) =>
        response.json.pipe(
          Effect.andThen(Schema.decodeUnknown(ErrorSchema)),
          Effect.andThen(handleErrors),
        ),
      ),
      Effect.scoped,
    );

  return { method1 };
});

export class ServiceName extends Effect.Tag(
  "@ampms-libs/package-name/ServiceName",
)<ServiceName, Effect.Effect.Success<typeof makeService>>() {
  static Live = Layer.effect(this, makeService);
}
```

## Schema Patterns

### Use Schema.Class for complex types

```typescript
export class ModelName extends Schema.Class<ModelName>("ModelName")({
  field1: Schema.String,
  field2: Schema.Number,
  optional: Schema.optional(Schema.String),
}) {}
```

### Use Schema.Struct for simple shapes

```typescript
export const ResponseSchema = Schema.Struct({
  data: Schema.Array(ModelName),
  count: Schema.Number,
});
```

### Branded types with static constructors

```typescript
export class QuoteSymbol extends Schema.Uppercased.pipe(
  Schema.brand("QuoteSymbol"),
) {
  static fromString(s: string): QuoteSymbol {
    return Schema.decodeSync(this)(s) as any;
  }
}
```

## Error Handling

### Define custom errors with Schema

```typescript
export class CustomError extends Schema.TaggedError<CustomError>(
  "@ampms-libs/package-name/CustomError",
)("CustomError", {
  code: Schema.Literal("ERROR_CODE"),
  description: Schema.String,
}) {}
```

### Use Match.type for error handling

```typescript
export const handleErrors = Match.type<ErrorUnion>().pipe(
  Match.tag("BadRequestError", (error) => new BadRequestError(error)),
  Match.tag("NotFoundError", (error) => new NotFoundError(error)),
  Match.orElse((error) => new UnknownError(error)),
);
```

### Always handle ResponseError

```typescript
Effect.catchTag("ResponseError", ({ response }) =>
  response.json.pipe(
    Effect.andThen(Schema.decodeUnknown(ErrorSchema)),
    Effect.andThen(handleErrors),
  ),
);
```

## Testing with @effect/vitest

### Test structure (REQUIRED pattern)

```typescript
import { FetchHttpClient } from "@effect/platform";
import { expect, layer } from "@effect/vitest";
import { Effect, Layer } from "effect";

const TestLayer = Layer.provide(ServiceName.Live, FetchHttpClient.layer);

layer(TestLayer)("ServiceName", (it) => {
  it.effect("should do something", () =>
    Effect.gen(function* () {
      expect.assertions(1);

      const result = yield* ServiceName.method();

      expect(result).toStrictEqual(expected);
    }),
  );
});
```

### Testing patterns

- **Always use** `Effect.gen` in test bodies
- **Always include** `expect.assertions(N)` for async tests
- Use `it.effect()` for Effect-based tests
- Use `it.effect.skip()` to skip tests
- Use `expect.objectContaining()` for partial matches
- Use `Effect.catchAll()` to test error cases

### Testing with mocks (RECOMMENDED for external APIs)

For services that call external APIs, use mock HTTP clients to avoid:

- Slow test execution (real API calls take seconds)
- Rate limiting issues
- Flaky tests due to network conditions
- Dependency on external service availability

**Mock HTTP client pattern:**

```typescript
import {
  HttpClient,
  HttpClientRequest,
  HttpClientResponse,
  UrlParams,
} from "@effect/platform";
import { Effect, Layer } from "effect";
import successResponse from "./fixtures/success-response.json";
import errorResponse from "./fixtures/error-response.json";

const createMockResponse = (
  request: HttpClientRequest.HttpClientRequest,
  status: number,
  body: unknown,
): HttpClientResponse.HttpClientResponse => {
  return HttpClientResponse.fromWeb(
    request,
    new Response(JSON.stringify(body), {
      status,
      headers: { "Content-Type": "application/json" },
    }),
  );
};

const handleMockRequest = (
  request: HttpClientRequest.HttpClientRequest,
): HttpClientResponse.HttpClientResponse => {
  const url = new URL(request.url);
  const path = url.pathname;
  const paramsString = UrlParams.toString(request.urlParams);
  const searchParams = new URLSearchParams(paramsString);

  if (path === "/api/resource" && searchParams.get("id") === "123") {
    return createMockResponse(request, 200, successResponse);
  }

  if (path === "/api/resource" && searchParams.get("id") === "error") {
    return createMockResponse(request, 404, errorResponse);
  }

  return createMockResponse(request, 404, { error: "Not mocked" });
};

const makeMockClient = Effect.sync((): HttpClient.HttpClient => {
  const execute = (
    request: HttpClientRequest.HttpClientRequest,
  ): Effect.Effect<HttpClientResponse.HttpClientResponse, never> => {
    return Effect.succeed(handleMockRequest(request));
  };

  // Don't apply filterStatusOk here - the real client already does it
  return HttpClient.make(execute);
});

export const MockHttpClient = Layer.effect(
  HttpClient.HttpClient,
  makeMockClient,
);
```

**Using mocks in tests:**

```typescript
import { MockHttpClient } from "./fixtures/mock-client";

const TestLayer = Layer.provide(ServiceName.Live, MockHttpClient);
```

### Fixture organization

Store test fixtures as JSON files in `test/fixtures/`:

```
test/
├── fixtures/
│   ├── mock-client.ts              # Mock HTTP client
│   ├── success-response.json       # Success fixture
│   ├── error-not-found.json        # Error fixture
│   └── partial-data.json           # Partial data fixture
└── service.test.ts                 # Tests
```

**Benefits of JSON fixtures:**

- Easy to update from real API responses
- Clear separation between mock logic and test data
- Can be validated independently
- Version control diffs are cleaner
- Can be generated from real API calls

**Creating fixtures from real API responses:**

```typescript
// Temporary script to capture real responses
import { FetchHttpClient } from "@effect/platform";
import { Effect, Layer } from "effect";
import { ServiceName } from "./src";

const TestLayer = Layer.provide(ServiceName.Live, FetchHttpClient.layer);

const captureResponse = Effect.gen(function* () {
  const result = yield* ServiceName.method({ id: "123" });
  console.log(JSON.stringify(result, null, 2));
}).pipe(Effect.provide(TestLayer));

Effect.runPromise(captureResponse);
```

Then save the output to a JSON file in `test/fixtures/`.

## Do's and Don'ts

### DO

- Use `Effect.gen` for all async operations
- Define schemas for all API responses and errors
- Follow the service pattern exactly
- Use peer dependencies for Effect ecosystem packages
- Write tests using `@effect/vitest`
- Use `Schema.decode` for runtime validation
- Handle errors with `Effect.catchTag`
- **Use mock HTTP clients for external API tests** (fast, reliable, no rate limiting)
- **Store test fixtures as JSON files** for easy maintenance
- **Generate fixtures from real API responses** to ensure accuracy

### DON'T

- Manually edit Projen-generated files
- Use Promise-based code (use Effect instead)
- Use `any` type (use `unknown` + Schema)
- Skip error handling in HTTP calls
- Forget `Effect.scoped` for resource cleanup
- Use `require()` (use ES6 imports)
- Commit without running tests (`pre-push` hook enforces this)
- **Test external APIs directly** (slow, flaky, rate-limited)
- **Inline large test fixtures** in TypeScript (use JSON files instead)
